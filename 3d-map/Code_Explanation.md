# Explanation Structure: приложение `3d-map`
 
## 1. Overview
Это приложение строит интерактивную 3D-карту на базе Giro3D/Three.js, загружая параметры карты и слоёв из `map_layers.json`.  
Карта поддерживает terrain deformation, hillshading, маску GeoJSON, переключение растровых слоёв и инструменты измерений (длина, площадь, высота, угол).

## 2. Step-by-Step Breakdown

### 2.1 Импорты и зависимости (`main.js:1-22`)
- Подключаются:
- `proj4` для преобразования координат между CRS (системами координат).
- OpenLayers (`GeoJSON`, `Style`) для чтения и стилизации маски GeoJSON.
- `three` и `MapControls` для камеры и управления сценой.
- Giro3D классы для карты, слоёв, источников данных и инструментов измерения.
- Почему так: код разделяет ответственность между библиотеками, каждая используется по своей сильной стороне.

### 2.2 Палитры и генерация градиента (`main.js:24-53`)
- `PALETTE_STOPS` задаёт базовые цветовые точки (`turbo`, `inferno`).
- `makeGradientFromStops(...)` интерполирует между цветами и строит массив из 256 оттенков.
- `makeColorMapColors(...)` выбирает:
- либо пользовательскую палитру из `style_config.palette`,
- либо предустановленную по `colormap_name`.

Пример сложного фрагмента с комментарием:
```js
for (let i = 0; i < shades; i += 1) {
  const t = shades <= 1 ? 0 : i / (shades - 1); // нормализуем позицию от 0 до 1
  const scaled = t * (stops.length - 1);        // перенос в диапазон индексов опорных цветов
  const idx = Math.floor(scaled);               // левый цвет
  const localT = Math.min(1, scaled - idx);     // доля смешивания к правому цвету
  colors.push(c0.lerp(c1, localT));             // линейная интерполяция цвета
}
```

### 2.3 Утилиты геометрии и режимов (`main.js:55-106`)
- `lonLatToProjected(...)`: переводит центр из `EPSG:4326` в рабочую CRS карты.
- `zoomToAltitude(...)`: считает высоту камеры по zoom и широте (аналог WebMercator масштаба).
- `buildHomeCamera(...)`: создаёт стартовую позицию камеры с учётом pitch/bearing.
- `parseBlendingMode(...)` и `parseMaskMode(...)`: безопасно переводят строку из JSON в enum.
- `layerZOrderValue(...)`: даёт дефолт `0`, если `z_order` невалиден.

### 2.4 Динамический UI для слоёв (`main.js:108-129`)
- `createLayerSwitch(...)` программно создаёт чекбокс слоя.
- `onToggle` приходит как callback, поэтому UI не знает деталей рендера (паттерн «инверсия управления» через колбэк).

### 2.5 Виджет измерений (`main.js:131-293`)
- Создаётся `DrawTool`, хранится массив созданных фигур `shapes`.
- Поддерживаются 4 режима: distance, area, height, angle.
- `AbortController` завершает текущий режим рисования при старте нового или по `Escape`.
- При смене единиц (`m/ft`, `m²/ha/acre`) вызывается `rebuildLabels()` для пересчёта подписей.
- `clear` удаляет все фигуры со сцены и синхронизирует UI.

Почему написано так:
- Это событийная модель (event-driven): кнопки и селекты обновляют только нужные части состояния.
- Логика вынесена во внутренние функции (`formatLength`, `startDrawing`) для переиспользования и меньшего дублирования.

### 2.6 Загрузка конфига (`main.js:295-301`)
- `loadConfig()` делает `fetch('./map_layers.json')`.
- При неуспехе HTTP кидает явную ошибку с кодом статуса.

### 2.7 Создание terrain-слоя (`main.js:303-320`)
- `createTerrainLayer(...)` собирает `GeoTIFFSource` + `ElevationLayer`.
- Берёт параметры из `elevation` секции JSON (`source`, `channels`, `min/max`, `resolution_factor`).

### 2.8 Основной bootstrapping (`main.js:322-643`)

#### Инициализация CRS и сцены (`322-342`)
- Регистрируется проекция через `proj4.defs` и `CoordinateSystem.register`.
- Центр карты трансформируется в целевую CRS.
- Вычисляется `extent` и создаётся `Instance` (корневая 3D-сцена Giro3D).
- Настраиваются Z-offset'ы, чтобы слои не «боролись» друг с другом за глубину (z-fighting).

#### Две overlay-карты: masked и unmasked (`344-391`)
- Создаются два `Map` с одинаковым `extent`, но разными условиями маски/освещения.
- Отдельной базовой подложки нет: базовый цвет сцены задаётся через `Instance.backgroundColor`, а все видимые данные рисуются overlay-слоями.
- Идея: быстро направлять слой либо в «маскированный» контур, либо в обычный рендер.

Аналогия: как два прозрачных стекла одно над другим, где одно стекло режется трафаретом (маской), а второе нет.

#### Terrain elevation и сортировка слоёв (`393-441`)
- Elevation слой добавляется только в один из overlay map (в зависимости от `is_masked`).
- Слои из `config.layers` сортируются:
- для рендера по возрастанию `z_order`,
- для UI-списка по убыванию `z_order` (пользователь видит «верхние» слои первыми).
- `layerVisibilityState` хранит видимость по `layer.id`.

#### Создание слоёв из JSON (`443-541`)
- Для `id === "elevation"` назначается `ColorMap` прямо `targetTerrainLayer` (не отдельный растровый слой).
- Для `type === "cog_rgb"` создаётся обычный `ColorLayer`.
- Для одноканального `cog_raster` создаётся `ColorLayer` + `ColorMap`.
- Каждый слой получает descriptor для UI-переключателя.

#### Подключение маски GeoJSON (`543-564`)
- Если включена `map.mask_layer`, создаётся `MaskLayer` с `VectorSource`.
- Поддерживается `mask_mode` (`normal`/`inverted`) и свой `data_projection`.

#### Сборка UI и камера (`566-597`)
- Из descriptor'ов строятся переключатели в `#layers-list`.
- Вычисляется home-камера, подключается `MapControls`, включается damping.
- Подключается `createMeasurementWidget(instance)`.

#### Обработчики UI (`598-636`)
- `terrain-deformation`: включает/выключает terrain на обеих overlay картах.
- `hillshading-toggle`: управляет lighting в masked/unmasked карте.
- `home-button`: возвращает камеру к сохранённому виду.
- `updateMaskVisibility()` скрывает overlay карты, если все слои выключены и hillshading тоже выключен.

#### Завершение (`638-643`)
- `bootstrap()` возвращает рабочие объекты.
- Ошибки инициализации логируются в `catch`.

### 2.9 Разметка и стили (`index.html`, `style.css`)
- `index.html` содержит:
- контейнер рендера `#view`,
- панель слоёв,
- переключатели hillshading/terrain,
- блок измерений и кнопку Home.
- `style.css` реализует плавающую панель поверх карты, переключатели в стиле toggle и сетку кнопок измерений.

### 2.10 Конфиг данных (`map_layers.json`)
- Файл полностью управляет поведением карты:
- CRS/центр/масштаб/поворот,
- включение terrain/hillshading,
- параметры маски,
- список растровых слоёв и их стили.
- Подход «конфигурация вместо хардкода» позволяет менять карту без правки `main.js`.

## 3. Key Concepts

### 3.1 Дизайн-паттерны
- Конфигурационный паттерн: бизнес-параметры вынесены в JSON, код универсален.
- Фабричные функции: `createTerrainLayer`, `createLayerSwitch` создают объекты по входным параметрам.
- Разделение ответственности (Separation of Concerns):
- чтение конфигурации,
- создание слоёв,
- UI-события,
- измерения.

### 3.2 Особенности JavaScript/ESM
- `import`/`export`-модель модулей (ESM).
- `async/await` для сетевой загрузки конфига.
- Nullish coalescing `??` и optional chaining `?.` для безопасных дефолтов.
- Стрелочные функции и колбэки в обработчиках событий.

### 3.3 Алгоритмы и структуры данных
- Линейная интерполяция цветов (`lerp`) для построения colormap.
- Двухпроходная сортировка слоёв (рендер и UI-порядок).
- `Map` как структура состояния видимости по ключу слоя (`id -> boolean`).

## 4. Potential Issues

### 4.1 Edge cases
- Нет валидации, что `map.center` имеет 2 числа; при битом JSON будут runtime-ошибки.
- Если DOM-элемент не найден (`getElementById` вернул `null`), код упадёт при доступе к свойствам.
- В `style_config.palette` сортировка идёт по `value`, но сами значения дальше не участвуют в нелинейной интерполяции (используются только цвета).

### 4.2 Производительность
- `instance.notifyChange(maskedMap/unmaskedMap)` вызывается часто; при множестве слоёв это может давать лишние перерисовки.
- Измерения хранят все фигуры в памяти до `clear`; при долгой сессии UI может тормозить.
- Большие COG-файлы + два overlay map увеличивают нагрузку на GPU/память.

### 4.3 Безопасность
- Прямых критичных уязвимостей в текущем коде не видно (нет `eval`, нет HTML-инъекций через `innerHTML`).
- Риск скорее эксплуатационный: если `map_layers.json` будет внешним/пользовательским, нужна строгая схема-валидация (например, через `map_layers.schema.json`) перед применением.

### 4.4 Улучшения
1. Добавить раннюю валидацию конфига по JSON Schema до `bootstrap`.
2. Проверять существование DOM-элементов с понятными ошибками.
3. Дебаунсить/батчить `notifyChange` в интенсивных сценариях.
4. Добавить отображение ошибок в UI (не только `console.error`).
5. Вынести крупные блоки `bootstrap` в модули (`layers`, `ui`, `camera`) для читаемости и тестируемости.

## 5. Usage Example

### 5.1 Запуск приложения
```bash
cd 3d-map
npm install
npm run dev
```
Открыть `http://localhost:5173/`.

### 5.2 Пример изменения слоя через конфиг
Ниже пример, как включить ортофото по умолчанию:
```json
{
  "id": "orthophoto",
  "name": "Orthophotomap",
  "type": "cog_rgb",
  "url": "./data/orthophoto_rgb.tif",
  "channels": [0, 1, 2],
  "is_active": true,
  "is_masked": true,
  "z_order": 3,
  "style_config": { "opacity": 1 }
}
```

### 5.3 Пример добавления пользовательской палитры
```json
{
  "style_config": {
    "palette": [
      { "value": 0, "color": "#00204d" },
      { "value": 0.5, "color": "#2ca58d" },
      { "value": 1, "color": "#ffe066" }
    ]
  }
}
```
Код автоматически отсортирует точки палитры и построит градиент.
